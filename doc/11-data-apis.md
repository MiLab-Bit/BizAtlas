# 11 · 数据 API 接入建议

> 对齐 PRD `06` · 工程数据层 [`04-data-layer.md`](./04-data-layer.md)  
> 原则：**上传资料是主源；外部 API 是补全与对标；任何源可降级。**  
> **占位已建：** [`../content/providers/registry.yaml`](../content/providers/registry.yaml) + `packages/data/providers/*` Stub；默认 snapshot，密钥稍后逐个 `enabled: true`。

---

## 1. 先按功能要数据，再选 API

| 产品能力 | 真正需要的数据 | 没有外部 API 能否演示 |
|---|---|---|
| 资料理解 | 财报三表、实体、引用 | ✅ 用户上传 PDF/Excel 即可 |
| 规则匹配 | 结构化指标 + 事件布尔值 | ✅ 上传 + fixtures |
| 风险提示·财务/经营 | 财务指标、集中度、同环比 | ✅ 上传抽取 |
| 风险提示·舆情/司法 | 失信、被执行、诉讼、处罚 | ⚠️ 需 API 或 fixtures 才能「一票否决」真香 |
| 风险提示·关联 | 股权、担保链 | ⚠️ 工商/司法图谱；MVP 用导出 JSON / fixtures |
| 投研整理 | 指标 + 行业对标 + 叙述 | ✅ 静态行业表可对标 |
| 流程辅助 | 清单状态，少依赖外数 | ✅ |

**结论：** 别一上来接十几个商业 API。先保证「上传闭环」，再按维度补 2–3 条稳定管线。

---

## 2. 推荐接入清单（按优先级）

### P0 · 必须接（W1–W2）

| API / 源 | 接什么 | 服务哪些功能 | 理由 |
|---|---|---|---|
| **用户上传**（内部） | PDF/Excel 财报、尽调包 | 资料理解、规则、评分、报告 | 主路径；私有化友好；赛题「读资料」本体 |
| **AKShare** | A 股三表、关键财务指标、股票基本信息 | 财务维度补全、行业对标样本、无上传时的上市企业快路径 | 零成本、接口面广；作 L1 候选之一 |
| **Tushare Pro**（有 token 则开） | 规范化财报、指标、公司基本面 | 同上；与 AKShare **互为降级** | 字段更稳；积分制，作「质量优先」源 |
| **本地 fixtures** | 三案例完整包（健康/风险/违约） | 答辩 snapshot、司法/担保链演示 | 无网可演；不依赖任何外网 API |
| **静态行业参数**（自建 JSON） | 行业均值、阈值覆盖 | 行业风险、对标条形图 | 不必接统计局实时 API |

> **财务双源策略：** `Tushare`（优先，若积分够）→ 失败切 `AKShare` → 再失败用上传解析 / 缓存。两者都不是工商司法源。

### P1 · 应该接（W3–W5，差异化）

| API / 源 | 接什么 | 服务哪些功能 | 理由 |
|---|---|---|---|
| **天眼查 API** *或* **企查查 API**（二选一） | 工商、股东、对外投资、司法诉讼、失信/被执行 | 关联风险、一票否决、担保链 KG | 护城河「隐性风险」靠它；**按量付费，先做查询预算与缓存** |
| **巨潮资讯 / cninfo**（HTTP 或封装） |  annoucement 列表与 PDF | 资料理解增强、公告事件规则 | 免费公告原文；补「没上传年报」时的抓取 |
| **企查查/天眼查导出 JSON**（无 API Key 时） | 与上同构字段 | 同上 | 演示与私有化试点的务实降级 |

**工商司法只选一家主供应商**，Provider 接口抽象，避免双账单。优先看：已有账号、单价、是否含「失信+被执行+股权穿透」。

### P2 · 可后接（智能化 / 体验）

| API / 源 | 接什么 | 服务哪些功能 | 备注 |
|---|---|---|---|
| 东财 / 新浪新闻检索（经 AKShare 或自建） | 标题、时间、情感粗分 | 舆情维度 | 噪声大；先关键词命中，别上复杂 NLP |
| 慧博 / 东财研报（爬取或付费） | 评级、摘要 | 投研 Memo | 版权与稳定性差，非 MVP |
| 国家统计局 / 公开宏观 | 行业增速 | 行业风险精化 | 可用季度手工更新表代替 |
| Wind / iFinD / Choice | 机构级全量 | 商业化试点 | 贵、对接重；Phase 4 |

### 明确不接 / 慎接（当前）

| 源 | 原因 |
|---|---|
| 行情级实时 tick / 交易 API | 产品不做交易与买卖建议 |
| 个人征信 / 个人信贷类 | 商业边界：只做企业/对公 |
| 裁判文书网裸爬生产化 | 合规与稳定性风险高；司法走商业 API 或导出 |
| 微信指数等强依赖爬虫 | 易挂；舆情用新闻源即可 |
| 多家工商 API 并行计费 | 成本与口径冲突；一家 + 缓存足够 |

## 3. Provider 落位（工程）

```
packages/data/providers/
  upload_financial.py      # P0 主源
  tushare_financial.py     # P0
  akshare_financial.py     # P0 降级/互补
  fixture_provider.py      # P0 snapshot
  industry_static.py       # P0
  qcc_or_tyc_company.py    # P1 工商司法（统一接口）
  cninfo_announcement.py   # P1
  news_sentiment.py        # P2
```

解析优先级（字段级）：

```
上传抽取 > Tushare > AKShare > 缓存 > 行业估算(L3) > 缺失标注
事件类（失信等）：商业工商 API > fixtures > 「未知」不否决
```

---

## 4. 和五维风险的接线

| 风险维 | P0 数据从哪来 | P1 补什么 |
|---|---|---|
| 财务 30% | 上传 + Tushare/AKShare | 巨潮公告交叉验证 |
| 经营 25% | 上传（客户/供应商集中度等） | 公告补披露 |
| 行业 15% | 静态行业表 + 上市同业 AKShare 分位 | 宏观增速 API |
| 舆情 15% | fixtures 事件 / 简单新闻 | 新闻 API + 处罚字段（工商） |
| 关联 15% | fixtures 担保链 | **天眼查/企查查** 股权与司法 |

一票否决（BLACK）字段：**失信被执行、破产重整** —— P0 用 fixtures 保证可演；P1 接真 API。

## 5. 成本与密钥

| 源 | 成本形态 | `.env` |
|---|---|---|
| AKShare | 免费（稳定性自担） | 无 |
| Tushare | 积分 / Pro | `TUSHARE_TOKEN` |
| 天眼查或企查查 | 按次 | `TIANYANCHA_TOKEN` 或 `QICHACHA_TOKEN` |
| 巨潮 | 免费抓取 | 无（注意频率与 UA） |

MVP 默认 `BIZATLAS_MODE=hybrid`：有 token 用真源，无 token 自动 fixtures + 上传。

---

## 6. 我建议的接线顺序（可执行）

1. **W1**：UploadProvider + FixtureProvider + IndustryStatic +（AKShare **或** Tushare 其一）  
2. **W2**：财务双源降级打通；指标进规则引擎  
3. **W3**：选定 **天眼查/企查查之一**，只接：工商概要、失信、被执行、诉讼列表、股权一级  
4. **W4**：巨潮公告列表（可选）；新闻舆情仍可用 mock  
5. **商业化前**：再评估 Wind/iFinD，替换免费财务源，不改 Provider 接口

---

## 7. 一句话

**接「上传 + AKShare/Tushare 财务双源 + 一家工商司法 + 巨潮公告」就够撑起商舆五能力；其余全部后置。** 答辩用 fixtures 托底，不把命运绑在爬虫稳定性上。
