## 一、数据类型概览

商舆 BizAtlas 作为企业经营与风险研判 Agent，涉及的数据按用途分为五类：

| 数据类型 | 用途 | 是否存储用户数据 | 风险等级 |
|---------|------|:---:|:---:|
| 企业公开财务数据 | 风险评分输入 | 否（公开信息） | 低 |
| 工商登记信息 | 主体识别与关联方分析 | 否（公开信息） | 低 |
| 司法/失信/被执行 | 一票否决风险事件 | 否（公开信息） | 低 |
| 用户上传文档（PDF/Excel） | 资料理解与指标抽取 | **是** | 中 |
| 对话指令与研判结果 | Agent 任务执行 | **是** | 中 |

## 二、数据来源与授权方式

本系统所有外部数据源的来源、授权状态与使用边界如下表（运行时可通过 `/v1/compliance/statement` 接口实时查询）：

| 数据源 | 来源性质 | 授权方式 | 使用边界 | 启用状态 |
|--------|---------|---------|---------|:---:|
| **用户上传解析** | 用户自有 | 用户主动上传，隐含授权 | 仅用于本次研判，不入库共享 | ✅ 已启用 |
| **演示案例 Fixtures** | 项目自有 | 内置脱敏构造数据 | 仅演示，不涉及真实企业 | ✅ 已启用 |
| **行业静态对标** | 公开统计 | 公共领域引用 | 用于行业基准比对 | ✅ 已启用 |
| **AKShare（同花顺源）** | 公开行情接口 | 开源协议（MIT），公开数据 | 财务指标抓取，遵守访问频率 | ✅ 已启用 |
| **Tushare** | 半公开接口 | 社区积分制 API Token | 限 1 次/分钟，仅研究用途 | ✅ 已启用 |
| **天眼查** | 商业 API | 商业授权（试用） | 工商/司法/关联方查询 | ✅ 已启用 |
| **企业 JSON 导入** | 用户自有 | 用户主动导入 | 用户提供的结构化数据 | ✅ 已启用 |
| **巨潮资讯（cninfo）** | 公开披露 | 证监会指定披露平台 | 公告与年报原文检索 | ✅ 已启用 |
| **AKShare 新闻** | 公开新闻聚合 | 开源协议 | 舆情事件抽取 | ✅ 已启用 |
| **企查查** | 商业 API | 商业授权 | — | ⬜ 未启用（待授权） |

**授权原则**：仅使用公开数据、用户主动提供的数据，或已获商业授权的 API；不抓取任何非公开或需绕过访问控制的数据。

## 三、用户数据处理与隐私保护

### 3.1 上传文档处理
- 用户上传的 PDF/Excel/TXT 文档**仅存储于本次会话的工作目录**，用于指标抽取与研判。
- 文档切片后建立**本地 RAG 索引**（SQLite），索引仅服务于本会话的引用溯源问答。
- **不上传至任何第三方云服务**；LLM 仅接收经脱敏处理后的摘要片段，不接触原始文档全文。

### 3.2 对话指令处理
- 用户输入的对话指令（如"分析某企业担保链风险"）在本地解析意图。
- 需调用 LLM 时，仅传递**研判所需的最小上下文**（指标摘要 + 规则命中），不传递企业完整敏感信息。
- 对话历史存储于本地 SQLite，用户可随时清除。

### 3.3 数据脱敏
- 演示案例（fixtures）中的企业均为**虚构脱敏主体**（healthy / risky / defaulted），不对应任何真实企业。
- 研判报告中引用的真实企业数据均来自公开披露渠道，未做额外脱敏（因本身为公开信息）。

### 3.4 不留存原则
- 本系统**不建立用户画像**、**不做跨用户数据关联**、**不向第三方共享用户数据**。
- 每次研判独立，不携带前序用户的历史上下文（除非同一用户同一会话内）。

## 四、行业风险提示与人工确认边界

### 4.1 风险等级与人工闸门

商舆对研判结果实施**强制人工复核机制**：

| 风险等级 | 分值区间 | 是否强制人工复核 | 说明 |
|---------|---------|:---:|------|
| 🟢 GREEN（低风险） | 0–20 | 否 | 可自动放行 |
| 🟡 YELLOW（中低风险） | 20–40 | 否 | 自动标注，提示关注 |
| 🟠 ORANGE（中高风险） | 40–60 | **是** | 强制人工复核 |
| 🔴 RED（高风险） | 60–80 | **是** | 强制人工复核 + 降额建议 |
| ⚫ BLACK（极高风险） | 80–100 | **是** | 一票否决，建议拒绝 |

**ORANGE 及以上等级，系统不自动做最终决策，必须由人工审批人确认。**

### 4.2 一票否决事件
以下事件一旦命中，无论分值高低，直接判为 BLACK：
- 被列入失信被执行人名单
- 进入破产重整程序
- 存在严重财务造假迹象

### 4.3 LLM 使用边界
- LLM **仅用于**：文档解析辅助、文案润色、意图识别。
- LLM **不用于**：关键数字计算、风险评分、最终决策。
- 润色输出若含未登记数字，**Gate 机制直接拒绝并回退模板句**——即"关键数字零幻觉"原则（对外表述为"数字可溯源"）。

## 五、不替代专业决策的边界声明

商舆 BizAtlas 是**辅助研判工具，不是征信机构，不替代专业信贷决策**：

1. **不是征信报告**：本系统输出的风险评分与审批建议，不构成中国人民银行认可的征信产品。
2. **不替代人工审批**：所有 ORANGE 及以上等级的决策必须经人工审批人最终确认；系统建议仅供参考。
3. **不构成投资建议**：本系统输出的企业分析不构成对任何证券的投资建议。
4. **准确性免责**：基于公开数据与规则引擎的研判结果可能因数据延迟、规则覆盖不全等原因产生偏差；使用者应结合实地尽调与专业判断综合决策。
5. **合规依赖**：本系统在金融场景的使用应遵守《个人信息保护法》《数据安全法》及行业监管要求。

## 六、评分有效性的诚实披露

商舆的风险评分经过**离线回溯验证**，验证结果作为产品内一等公民公开（而非仅写在 PPT 里）：

- **验证指标**：AUC = 0.630（95% 置信区间 [0.582, 0.676]）；KS = 0.211
- **样本**：675 条记录（正样本 480 条 ST 企业 + 负样本 195 条非 ST 企业）
- **诚实局限**：
  - 本次回溯仅喂入财务维度，未纳入工商/司法/担保图谱/舆情等外部事件——单源下区分力有限属预期。
  - 正样本为"名称含 ST"的代理标签，存在已摘帽但名称未改的情况，会稀释区分度。
  - 提前预警期指标因免费数据源无法取得 ST 实施起始年而暂缺，待接入权威事件库后补算。
- **不编造**：若回溯报告未生成，前端接口显式返回"暂不可用"而非给出推测数字。

完整验证报告可通过 `/v1/validation/backtest` 接口实时查询，或查看仓库 `backtest_report.json`。

## 七、运行时合规自检

本系统提供运行时合规自检接口，确保声明与实际运行一致：

```
GET /v1/compliance/statement
```

返回内容包含：
- 产品定位（是什么 / 不是什么）
- 数据源授权矩阵（声明启用 vs 实际启用，自动对账）
- 运行一致性徽章（consistent / running_not_declared / declared_not_running）
- 治理声明与免责条款

**若实际运行的数据源与声明不符，系统会自动标记为 `running_not_declared` 并提示修正**，确保对外披露与实际行为始终一致。
